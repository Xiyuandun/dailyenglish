# DailyEnglish · 语音与语音识别方案

> 核心代码：`js/speech.js`（约 1600 行）。所有朗读与录音识别都由这一个对象 `Speech` 管理。

## 一、朗读（TTS）的整体架构

### 「无后端也有自然声音」的真相

关键不在"实时合成"，而在 **"提前合成好、存成本地 MP3"**。流程图：

```
用户点击"🔊 朗读"
   ↓
查 window.STATIC_AUDIO 清单（data/audio.js）
   ├─ 命中 → 播放 audio/xxx.mp3（edge-tts 神经语音，离线、零后端、自然）
   └─ 未命中 → 走动态通道（见下）
```

- `data/audio.js` 定义 `window.STATIC_AUDIO`，分 `normal`（常速）和 `slow`（慢速）两组，把**英文原文**映射到 `audio/` 下的 MP3 文件名。
- 这些 MP3 是部署前用 **edge-tts**（微软神经网络语音）一次性生成的，比如 Jenny 女声。
- `_staticAudioPath(text, rate)` 负责把待读文本**规范化**（去空白、统一小写、压缩空格）后查清单；命中返回 `audio/文件.mp3`，交由 `_playStatic()` 播放。
- **这就是 GitHub Pages 等纯静态站也能有自然声音的原因**：声音不是网页运行时生成的，而是早就做成了静态文件。

### 动态朗读的完整优先级链（当静态清单未命中时）

`_dispatchSpeak(text, rate)` 的判定顺序为：

1. **静态预生成音频**（`audio/` 本地 MP3）→ 最优先，最稳定。
2. **云端 TTS**（`useCloudTTS`，请求后端 `/tts`，用 edge-tts 实时合成）——仅本地或 Render 后端启用。
3. **Google TTS**（`useGoogleTTS`，直连 translate.google.com，免费无 key）。
4. **安卓**：若有浏览器英语语音 → HTTP Web Speech；否则 → 有道 TTS。
5. **非安卓**：有 `speechSynthesis` → 浏览器内置语音；否则 → 有道 TTS。

### 各通道说明

| 通道 | 用途 | 特点 |
|------|------|------|
| 静态音频 | 聊天/单词/场景等预置文本 | 效果最好、无网络依赖 |
| 云端 TTS `/tts` | 动态文本（本地/Render） | 实时，edge-tts，Jenny 等 |
| Google TTS | 静态环境动态文本 | 免费，但国内网络可能被屏蔽 |
| Web Speech（浏览器内置） | iOS/桌面 | 无需网络，但音色机械、安卓不稳定 |
| 有道 TTS | 落魄时的兜底 | 有长度限制(180字符)、易挂起 |

> 行业查询耗时问题：Google/有道/云端 TTS 都易受网络、限流影响，所以**凡是常读的句子都尽量提前塞进静态清单**，这是整个项目语音稳定的核心手段。

## 二、iOS / 移动端扬声器解锁

`init()` 里用首次用户手势解锁：

- **Audio 解锁**：用一个静音 base64 WAV `play()` 一下，解除 iOS 对 Audio 播放的限制。
- **Web Speech 预热**：首次触摸时用一条**非空的超短** utterance（`'Hi'`，volume 0、rate 10）讲一次，`cancel()`→`pause()`→`resume()`，修复 iOS 首次 speak 偶发无声。

## 三、朗读队列与防卡死

`speakQueue(texts, rate)` 用于"全文朗读/多句连续朗读"：

- 事件驱动：每句 `audio.ended` 后自动播下一句（`_advanceQueue`）。
- **卡死监视** `_armQueueWatcher`：按句长估算朗读时长，超时仍未播放/推进则**强制跳到下一句**，避免"有道挂起 / iOS 首句无声 / 某句卡住"导致整段静默。
- 有道 TTS 有 180 字符上限，长文本用 `_splitText` 自动分句。
- 切换 Tab、隐藏页面、退出时统一 `Speech.stop()` 清队列（见 app.js）。

## 四、语音识别（STT）

"录音跟读打分"功能，历史上经历过多套方案，当前默认**纯前端**。

### 当前默认（最终方案：纯前端，无需后端）

识别通道按下列规则自动选择（`_useCloudSTT()` 判定）：

1. **云端识别**（阿里云 DashScope Paraformer）：仅当 `window.DAILY_CFG.sttUrl` 配置了**绝对地址**（GitHub Pages 前端 + 独立后端 IP），或页面本身由后端（本地/Render）提供时才启用。
2. **浏览器 Web Speech**（`SpeechRecognition` / `webkitSpeechRecognition`）：iOS/iPad、桌面优先，无需下载模型。
3. **Vosk 离线模型**：安卓或无 Web Speech 的设备，下载约 40MB 模型本地识别（零云端）。

> 纯静态部署（未配置 sttUrl）时 `sttBase` 为空 → 全程走离线 Vosk / 浏览器 Web Speech，**不依赖任何后端**。

### Vosk 离线识别要点

- 库 `js/vendor/vosk-browser.js`（约 5.4MB）**按需动态加载**，避免拖慢首屏。
- 模型切 3 片（<20MB）放 jsDelivr CDN 分片下载后合并（jsDelivr 大陆有加速节点且带 CORS）。
- 模型地址可经 `window.DAILY_CFG.renderModelUrl` 指到后端托管，绕开 GitHub Pages 下载超时。
- 有下载进度条、失败自动重试。

## 五、可选声音（edge-tts 音色）

前端可切换 7 种英语音色（存 `Store.voice`）：

| key | edge 音色 | 描述 |
|-----|-----------|------|
| jenny | en-US-JennyNeural | 女声·自然（默认，类似豆包） |
| aria | en-US-AriaNeural | 女声·温暖 |
| guy | en-US-GuyNeural | 男声·自然 |
| davis | en-US-DavisNeural | 男声 |
| amber | en-US-AmberNeural | 女声 |
| emma | en-GB-EmmaNeural | 英式女声 |
| brian | en-GB-BrianNeural | 英式男声 |

> 静态清单里的 MP3 是按 Jenny 生成的一套。若切换其他音色，动态通道会实时合成该音色，但静态命中时播放的是预先固定的声音。

## 六、可选后端（server.py）的行为

完整后端 `server.py` 提供：

- `/tts?text=..&voice=..&rate=..&volume=..`：edge-tts 实时合成 MP3，带 MD5 磁盘缓存（`tts_cache/`）。
- `/stt`（POST）：接收浏览器上传的 raw PCM（16kHz 单声道 base64），调用阿里云 DashScope Paraformer 识别，返回 `{text}`。
- 静态文件托管 + CORS + JS/CSS 禁用缓存。
- `DASHSCOPE_API_KEY` 通过环境变量注入，绝不硬编码进仓库。
- 本地开发走代理 18080（`HTTP_PROXY`），云平台通过环境变量配置。

# DailyEnglish · 部署方式与开发历史

## 一、部署方式总览

这个项目支持「纯静态」和「带 Python 后端」两种部署，根据 `speech.js` 的 `location.hostname` 自动切换行为。

### 1. 纯静态部署（最简单，推荐）

**GitHub Pages / Vercel / 任意静态托管**均支持：
- 只上传 `index.html`、`css/`、`js/`、`data/`、`audio/`（若用 Vosk 识别还需 `models/`）。
- 无需任何后端。朗读靠预生成的 `audio/*.mp3` + 浏览器语音；识别靠浏览器 Web Speech / Vosk 离线模型。
- **`vercel.json`** 为 Vercel 的 `/models/` 添加 CORS 头和长缓存，解决模型文件跨域下载。
- 项目根有 `.nojekyll`（GitHub Pages 用，跳过 Jekyll 处理）。

### 2. Python 后端部署（要云端 TTS / 云端 STT）

**`server.py`** 承担：静态文件 + `/tts`（edge-tts 实时合成）+ `/stt`（阿里云 DashScope 识别）。

- **本地**：`python3 server.py 8000`（需 `pip install -r requirements.txt`）。
- **Render 云平台**：`render.yaml` 配置了 Python 3.11、启动命令 `python server.py`。仅启用云端 TTS 时用；`/stt` 还需配 `DASHSCOPE_API_KEY` 环境变量。
- **阿里云函数计算（FC）**：`fc_deploy/` 目录承载 `/stt` 云端语音识别入口（历史方案，已基本弃用）。

### 3. 辅助/开发工具

| 文件 | 用途 |
|------|------|
| `proxy_connect.py` | SSH 代理隧道：`ssh -o ProxyCommand="python3 proxy_connect.py %h %p" user@host` |
| `tunnel.py` | localtunnel 内网穿透客户端，把本地服务暴露成公网 URL（支持走 18080 代理） |
| `requirements.txt` | `edge-tts>=6.1.0`、`dashscope>=1.14.0` |

## 三、如何复现"无后端自然声音"

1. 用 edge-tts 把需要朗读的英文文本预先生成 MP3，放进 `audio/`。
2. 在 `data/audio.js` 的 `window.STATIC_AUDIO.normal`（常速）/`.slow`（慢速）里登记「原文 → 文件名」映射。
3. 前端 `_dispatchSpeak` 优先查此清单，命中即播放本地 MP3 —— 稳定、离线、自然，且无需任何后端。

> 这正是韩语版 (`dailykorean/`) 复刻的核心机制：用 `tools/gen_audio.py` + edge-tts 生成韩语神经语音 MP3，配 `data/audio.js` 清单，实现"无后端自然韩语"。
